# 现在你要做什么：MSPM0G3507 电赛小车传感器任务单

你现在不要急着“直接烧录然后跑车”。正确顺序是先确认工程能编译、能下载、串口能输出，再分别调灰度和 ICM42688。下面每个任务完成后再进入下一步。

## 任务 0：准备工具

你需要准备：

- 地猛星 MSPM0G3507 开发板。
- ICM42688 模块。
- 亚博智能八路灰度寻线模块绿光款。
- USB 数据线或调试器。
- USB-TTL 串口模块，或者开发板自带虚拟串口。
- CCS。
- TI MSPM0 SDK，工程当前按 `mspm0_sdk@2.11.00.07` 配置。
- SysConfig，工程当前按 `1.26.2` 配置。

## 任务 1：不要先接全部模块

第一次上电时只接：

1. MSPM0G3507 开发板。
2. 调试器/下载器。
3. 串口线，如果你需要看 UART 打印。

暂时不要接电机、舵机、12V 电源和其它大电流模块。这样做是为了避免代码还没跑通就因为供电或接线问题烧板。

## 任务 2：在 CCS 中导入工程

1. 打开 CCS。
2. 选择 `File -> Import`。
3. 选择 `Code Composer Studio -> CCS Projects`。
4. 工程目录选择仓库里的 `hui du` 文件夹。
5. 勾选识别出的工程。
6. 点击 `Finish`。
7. 打开 `empty.syscfg`，确认芯片是 MSPM0G3507。

如果 CCS 提示 SDK 或 SysConfig 版本不一致，先不要改代码，先把提示截图发给我。

## 任务 3：先确认能编译

在 CCS 里点击 Build。

你要得到下面任意一种结果：

- 成功：继续任务 4。
- 失败：把完整报错复制给我，不要只发截图，也不要自己乱改。

如果报错和 `ti_msp_dl_config.h` 有关，通常说明 SysConfig 没有重新生成或 SDK 路径不对。

## 任务 4：确认能下载和运行

1. 点击 Debug 或 Download。
2. 程序下载到 MSPM0G3507。
3. 运行程序。
4. 观察 OLED 或 LED 是否有变化。

如果下载失败，把 CCS 的错误提示发给我。

## 任务 5：确认串口打印

当前工程串口设置：

| 项目 | 设置 |
| --- | --- |
| UART | UART0 |
| TX | PA28 |
| RX | PA31 |
| 波特率 | 115200 |

你的连接方式：

| MSPM0G3507 | USB-TTL |
| --- | --- |
| PA28 TX | RXD |
| PA31 RX | TXD |
| GND | GND |

串口助手设置：

- 波特率：115200。
- 数据位：8。
- 停止位：1。
- 校验：无。

如果串口乱码，优先检查波特率和 TX/RX 是否交叉。

## 任务 6：先验证 ICM42688 是否在线

当前工程主程序会初始化 ICM42688，并读取 `WHO_AM_I`。正常情况下 OLED 会显示 ICM42688 状态，串口会打印 ICM42688 数据。

你需要做：

1. ICM42688 接 3.3V，不要接 5V。
2. GND 必须和主控共地。
3. 按工程注释确认引脚：PA15=SCL、PA14=SDA、PA13=CS、PA16=AD0。
4. 下载运行。
5. 看串口是否输出加速度和角速度。

如果显示 `ICM42688 not found`，先检查：

- CS 是否接到 PA13，并且被拉高。
- AD0 是否接到 PA16，并且被拉低。
- SCL/SDA 是否接反。
- 模块是否有 I2C 上拉。
- 模块供电是否为 3.3V。

## 任务 7：再配置灰度模块

灰度模块接线：

| 灰度模块 | MSPM0G3507 | SysConfig 类型 |
| --- | --- | --- |
| 3V3 | 3.3V | 电源 |
| GND | GND | 电源地 |
| AD0 | PA0 | GPIO 输出 |
| AD1 | PA1 | GPIO 输出 |
| AD2 | PA2 | GPIO 输出 |
| OUT | PA27 | ADC 输入 |

你要在 SysConfig 中新增：

1. PA0 GPIO 输出，默认低电平。
2. PA1 GPIO 输出，默认低电平。
3. PA2 GPIO 输出，默认低电平。
4. PA27 ADC 输入，单次采样即可。

如果你不会在 SysConfig 里配 ADC，不要自己乱选，把界面截图发给我，我下一步可以专门教你配 PA27 ADC。

## 任务 8：把 ADC 读取函数接给灰度驱动

`gray.c` 已经负责选择 8 路通道。当前工程已使用 SysConfig 生成的
`GRAY_ADC_INST` 和 `GRAY_ADC_ADCMEM_GRAY_ADC_MEM` 宏实现 PA27 单次采样，
并在每轮主循环打印 `GRAY:` 后面的 8 路原始值。

```c
static uint16_t ReadGrayAdc(void); // 实现见 main.c
```

然后初始化：

```c
Gray_Init(ReadGrayAdc);
```

读取 8 路：

```c
uint16_t gray[GRAY_CHANNEL_COUNT];
Gray_ReadAll(gray);
```

烧录后应先看到 `FW: GRAY_ADC_DIAG_V5` 和 `GRAY ADC ready: PA27, 8 channels`，
随后每轮看到 `GRAY: ch0 ch1 ch2 ch3 ch4 ch5 ch6 ch7`。
如果紧接着出现 `ADC_TIMEOUT`，说明 ADC 转换未完成；如果没有超时但 8 路始终为
0，则应测量灰度模块 `OUT` 对 GND 的电压并检查模块供电、共地和 PA27 接线。

## 任务 9：记录黑白数值

把灰度模块放在白色地面上，记录 8 路 ADC 值。再把它放在黑线上，记录 8 路 ADC 值。

你要发给我这样的数据：

```text
白底：3100 3050 3080 3120 3090 3070 3110 3060
黑线：900  850  870  920  880  860  910  890
```

我会帮你判断：

- 黑线是高电平还是低电平。
- 阈值应该取多少。
- `blackIsHigh` 应该填 0 还是 1。

## 任务 10：再接电机，不要提前接

只有当下面三项都成功后，才接电机驱动：

- 串口正常打印。
- ICM42688 能读到数据。
- 灰度 8 路能读到黑白变化。

接电机之前先把车架悬空，避免电机突然全速转导致车冲出去。

## 现在最重要的一句话

你现在不是“直接烧录就行”，而是：

1. 先导入工程。
2. 先编译。
3. 再下载。
4. 先看串口和 OLED。

6. 再单独调灰度。
7. 最后才接电机做循迹。
