# MSPM0G3507 复位与调试锁定审计

## 结论

对 `hui du/` 中的 C、头文件、SysConfig、链接脚本和目标配置进行关键字检查后，
没有发现以下行为：

- 软件复位或系统复位 API；
- 看门狗初始化或喂狗代码；
- NONMAIN、BCR、BSL 或调试访问保护写入；
- Flash 擦除、写入、量产锁定或密码配置；
- 把 SWDIO PA19 或 SWCLK PA20 配置成普通 GPIO。

`empty.syscfg` 只把 PA19/PA20 建议分配给 DEBUGSS。主程序中的两个
`while (1)` 都是正常的应用循环：一个用于 ICM42688 初始化失败后的 LED
提示，另一个是传感器采样主循环；它们不会永久锁定调试接口。

## 排查边界

“无法连接目标”不能直接等同于芯片被安全锁定。应先区分：

1. CCS 工程/目标芯片或封装选择错误；
2. 调试器、USB、电源或复位线异常；
3. 用户本机 SysConfig 生成文件与仓库版本不同；
4. 应用时钟配置导致程序异常，但调试口仍可在复位下连接；
5. 用户烧录过仓库之外、会修改 NONMAIN 的固件；
6. 芯片确实启用了调试安全保护。

恢复操作前应保存 CCS 的完整错误信息。不要在错误原因不明时反复执行
Factory Reset/Mass Erase，因为这些操作会清除程序和校准数据。

## 仓库侧预防措施

bringup 工程不需要 PLL 性能。为减少错误时钟树导致 CPU 启动后无法被调试器
暂停的风险，`empty.syscfg` 保持默认 SYSOSC，不再切换到 SYSPLL2X；目标配置的
SWD TCLK 也降为 100 kHz，优先保证恢复连接的可靠性。用户必须先恢复
`Connect Target`，才能重新生成、编译和下载这份配置；修改电脑端源码本身不能
解除已经运行在芯片中的旧固件。
